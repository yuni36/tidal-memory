# 花费与账单口径

> 维护者实测，不是报价。单价以供应商官网为准；仓库不内置实时价格。  
> 想要“能不能便宜点”的结论：主聊看缓存和输出长度；积温分析可以走免费层；记忆/摘要用便宜模型。

---

## 1. 维护者配置

| 项 | 配置 |
|---|---|
| 服务器 | 2 核 4G VPS（自备） |
| 端口 | relay `3011` / memory `3013` / Chroma `7707` / 通知服务占一个端口 |
| 主聊 | Gemini 原生，偏好长回复 |
| 积温分析 | Gemini flash lite 免费层 |
| 记忆 / 事件线摘要 | DeepSeek |

服务器、域名、代理不计入下面的 API 账单。

---

## 2. 实测

| 项目 | 量级 |
|---|---|
| 日均消息 | ~190 句 |
| 平均输入 | ~1 万 token/次（人设 + 历史 + 记忆 + 工具） |
| Gemini 缓存命中 | 90%+ |
| 主聊 | ~$0.5/天 |
| 积温分析 | 免费层额度内 ¥0 |
| 记忆 / 事件线摘要 | ~¥0.5/天 |
| **API 合计** | **约 ¥120/月**（按 $1≈¥7.1） |

反推：$0.5 ÷ 190 ≈ **$0.0026/轮**（约 0.26 美分）。

---

## 3. 账单归属（别混）

| 账单 | 谁产生 | 用什么模型 | 备注 |
|---|---|---|---|
| 主聊 | 每条用户消息 + 主动来找 | Gemini 原生 | 主动来找是完整一轮，计入这里 |
| 积温分析 | 每条用户消息（分析开关开） | Gemini flash lite | 免费层；超限只 fallback |
| 记忆 / 事件线 | 后台整理 / 周期摘要 | DeepSeek | ~¥0.5/天 |
| 手动主动关怀 | 设置页“发一条”按钮 | 记忆管线模型 | 与自动积温不是同一条 |

**聊天账单 ≠ 记忆账单。** 如果你给记忆 / 积温各用一把 Key，供应商控制台也是不同账单，不要只拿“聊天发票”对总支出。

---

## 4. 积温为什么可能免费

代码里积温由几条路径组成：

- **数学时钟**：每 5 分钟 tick，不调 LLM，不花钱。
- **主动来找**：到阈值后由 brain 开完整一轮，用**聊天模型**，计入主聊。
- **情绪分析**：只有打开“启用情绪分析”才会调 `affect_*`；可配 Gemini flash lite 免费层。
- **语调染色**：本地 tone grid，不调 LLM，不花钱。
- **手动“发一条”**：走记忆管线，和自动积温不同。

免费层注意：

- 有 RPM / RPD 限额，以 Google 官方当前额度为准；
- 额度超限 / 429 / 超时：只做兜底，不挡主聊；
- 代码不会自动切到付费模型，也不会借用聊天 / 记忆 Key。

## 5. 成本公式

```text
日成本 ≈ N × [ 未命中输入 × in价 + 命中输入 × cached_in价 + 输出 × out价 ] / 1,000,000
```

- `N`：当天 LLM 调用次数（含工具 / 重试的中间轮）；
- 输入 token 包含缓存命中：未命中 = `input_tokens - cached_tokens`；
- 单价填 `model_prices`，单位 **USD / 百万 token**，含 `in` / `cached_in` / `out`；
- 长回复主要抬 `out`，缓存只省输入。

---

## 6. 为什么低，为什么还会高

**低的原因：**

- 稳定前缀命中 90%+，1 万输入里约 9 千只按 cached 价；
- 积温分析走免费层；
- 记忆 / 事件线用 DeepSeek，单价比主聊低。

**会变高的时刻：**

- 首次建缓存、改人设 / 提示词、换模型；
- 隔夜缓存过期，第二天第一轮全价；
- 开 Gemini 搜索 grounding（另有额度 / 费用）；
- 记忆整理频率调高、积温分析开关常开且额度超限后仍反复重试；
- 长回复、长上下文、工具链中间轮多。

---

## 7. 怎么和供应商账单对

1. 用量页 `web/usage.html` 按模型名聚合 token；模型名要和请求里的 `model` 字符串一致。
2. 在设置里填 `model_prices`（USD / 百万 token）；改价能重算历史展示，不会改旧记录。
3. 未标价模型会进 `unpriced_models`，页面显示 `?`，补价即可。
4. 聊天 / 记忆 / 积温各用一把 Key 时，供应商控制台是**多路账单**，要分别对。
5. 失败重试、搜索 grounding、嵌入调用可能不在同一张账单里。

---

## 8. 预算控制

- 在供应商控制台设月度限额 / 告警。
- 不用的旁路关掉：积温分析、搜索、摘要、天气。
- `GROUNDING_MONTHLY_LIMIT` 设本地月硬顶（默认比官方额度更保守）。
- 记忆 / 事件线用 DeepSeek 这类便宜模型。
- 积温分析用 Gemini flash lite 免费层，并接受“超限就跳过”。
- 先本机跑通，再上云；不要一上来就开全部旁路。

---

## 9. 常见误解

| 误区 | 实际 |
|---|---|
| “缓存 = 记忆” | 不是。缓存是模型前缀；记忆是星图 / 检索 |
| “90% 命中 = 省 90%” | 不是。输出不缓存，长回复仍按原价 |
| “积温免费 = 主动来找免费” | 不是。主动来找走聊天模型，计入主聊 |
| “积温不配 API 就不会来找” | 不是。数学时钟照跑；只是不分析情绪 |
| “手动发一条失败 = 自动积温坏了” | 不一定。手动走记忆管线，自动走聊天模型 |
| “仓库自带价格” | 没有。`model_prices` 默认空，要自己填 |
